# ADR-001. Архитектура: гибрид, официальный MCP как транспорт

Статус: принято 2026-09-28 по итогам спайка `docs/spike/2705.1.25.md`.

## Контекст

Нужен инженерный слой уровня build123d-mcp поверх Autodesk Fusion. Официальный Fusion MCP (tech preview) уже включён на `127.0.0.1:27182/mcp`.

## Решение

В проектном `.cursor/mcp.json` два сервера:

- `fusion-official` — документация API, скриншот, скрипты только с `readOnly: true`, undo/redo;
- `fusion-cad-ai` — stdio-сервер этого репозитория. Он ходит в Fusion через `OfficialMcpTransport`.

`FusionTransport` имеет три реализации: `official`, `fake` (тесты), `bridge` (клиент есть, add-in не поставляется).

Свой add-in не входит в поставку. Условия из плана, при которых его надо было бы включить:

| Условие | Факт спайка |
|---|---|
| Состояние Python не сохраняется | Сохраняется (`sys.modules`) |
| p95 задержки > 3 с | p50 0.142 с, max 0.225 с |
| Упор в размер скрипта | Модели — десятки КБ, лимит не достигнут |
| Нестабильность tech preview | 502 был из-за отсутствия `Expect: 100-continue`, это чинится на клиенте |

Повторно открыть вопрос, если контрактный тест официальных инструментов упадёт с `CONTRACT_CHANGED` и адаптер не починить за один проход.

## Последствия

Каждый вызов — новый скрипт `def run(_context)`. Сессия (namespace `execute`, реестр имён, snapshots, jobs) живёт в модуле `fca_rt`, который загрузчик держит в `sys.modules`. Смена хеша исходников перезагружает код и переносит объект сессии.
